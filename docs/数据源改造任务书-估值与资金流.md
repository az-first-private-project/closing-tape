## 0. 背景与目标

当前系统两个数据边界导致部分因子链路无法在纯真实数据上出信号：

1. **估值数据缺口**：历史日线只有 OHLCV，A1/A4（估值类）与 A3（价值/质量因子）出不了真实信号（目前混有演示数据）。
2. **板块/资金流单源依赖东财**：东财请求被"网络重置"时，板块热力图与 A2 资金流整块为空。

本次改造目标：**不引入付费源**，用实测可行的免费链路打通估值历史，并将板块/资金流做成多源降级架构。

## 2. T1：baostock 估值字段 + 回填（P0）

### 2.1 修改点

日线采集的 `query_history_k_data_plus` fields 从 OHLCV 扩为：

```python
fields = ("date,code,open,high,low,close,preclose,volume,amount,"
          "turn,tradestatus,pctChg,peTTM,pbMRQ,psTTM,pcfNcfTTM,isST")
```

对应改动：
1. 日线表新增 4 列：`pe_ttm NUMERIC, pb_mrq NUMERIC, ps_ttm NUMRIC→NUMERIC, pcf_ncf_ttm NUMERIC`（建议再加 `is_st SMALLINT`）。用 alembic 迁移脚本，不要 `create_all` 硬改（本项目分区表，create_all 不会改已有表）。
2. 采集入库逻辑映射上述字段；baostock 空值返回 `""`，落库前转 `None`，**不要转 0**。
3. 回填脚本：对股票池全量重新拉取日线（或单独的估值回填脚本按 `date,code,close,peTTM,pbMRQ,psTTM,pcfNcfTTM` 拉），幂等 upsert。
4. baostock 限速：请求间隔 ≥0.3s，失败重试用 tenacity（依赖已有），最多 3 次退避重试。

### 2.2 验收标准

- [ ] 任意一只样本股（如 sh.600000）日线表最近 250 个交易日 `pe_ttm/pb_mrq` 非空率 > 95%（停牌日除外）
- [ ] `pe_ttm` 与收盘价联动合理：同一天 close 上涨而 pe 下降的记录占比 < 1%（防字段错位）
- [ ] 空字符串一律落库为 NULL，无 `0` 假数据
- [ ] A1/A4/A3 因子计算改读真实估值列，`use_demo_data` 开关对估值因子不再生效

### 2.3 风险与口径说明

- baostock 的 peTTM/pbMRQ 与东财口径可能有细微差异（TTM 计算时点不同）。**因子分位数阈值必须基于回填后的新数据重新计算**，不得沿用演示数据混算期的阈值。
- baostock 私有 TCP 协议（服务器端口非 HTTP），Docker 容器内需可出网；容器内无代理 env 干扰，属干净环境。

## 3. T2：清代理 + 东财 curl_cffi fetch 层（P0）

### 3.1 统一网络入口（新建 `app/data/http_client.py`）

```python
"""所有采集请求统一走此模块，禁止在业务代码里直接 import requests。"""
import os

# 国内数据源直连：清掉继承的全局代理，走代理反而被重置
for _k in ("HTTP_PROXY", "HTTPS_PROXY", "http_proxy", "https_proxy"):
    os.environ.pop(_k, None)
os.environ["NO_PROXY"] = "*"

from curl_cffi import requests as cffi_requests

EM_HEADERS = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"}

def em_get(url: str, *, params: dict | None = None, retries: int = 3, timeout: int = 15) -> dict:
    """东财接口专用：curl_cffi 伪装 Chrome TLS 指纹（实测 requests 会被重置）。"""
    last_exc = None
    for i in range(retries):
        try:
            r = cffi_requests.get(url, params=params, headers=EM_HEADERS,
                                  impersonate="chrome", timeout=timeout)
            r.raise_for_status()
            return r.json()
        except Exception as e:  # noqa: BLE001
            last_exc = e
            import time; time.sleep(2 ** i)
    raise ConnectionError(f"eastmoney fetch failed: {url} -> {last_exc}")

def plain_get(url: str, **kw) -> "cffi_requests.Response":
    """非东财源（同花顺/乐咕等）通用 GET，同样直连。"""
    return cffi_requests.get(url, headers=EM_HEADERS, timeout=kw.pop("timeout", 15), **kw)
```

要点：
- 模块级 `os.environ.pop` 在 import 时即生效，所有采集脚本入口必须 import 此模块且 import 顺序在 akshare 之前（akshare 内部 requests 读 env）。
- akshare 的东财接口（如 `stock_board_industry_name_em`）内部用 requests，会被重置。**改法二选一**：
  - 方案 A（推荐）：东财相关采集不再调 akshare 的 em 接口，改用 `em_get` 直调 push2 JSON 接口，自己解析字段。接口样例（已实测 200）：
    `https://push2.eastmoney.com/api/qt/clist/get?pn=1&pz=100&fs=m:90+t:2&fields=f3,f12,f14`
  - 方案 B：monkeypatch `requests` 的 TLS 适配层 —— 复杂且脆，不推荐。
- 重试已内置指数退避；全市场批量采集需额外限速（≥0.5s/次），避免触发真风控。

### 3.2 验收标准

- [ ] 在带全局代理 env 的终端跑采集脚本，东财接口正常返回（ProxyError 消失）
- [ ] `stock_board_industry_name_em` 等原失败接口的替代实现返回行数与浏览器访问一致（行业板块 ~86 行）
- [ ] 业务代码中无直接 `import requests`（grep 检查 `app/` 目录）

## 4. T3：板块/资金流双源 + provider registry（P1）

### 4.1 设计

沿用现有 `DATA_PRIMARY_PROVIDER` / `DATA_FALLBACK_PROVIDER` 思路，扩展为 **per-数据域** 的注册表：

```python
# app/data/providers/registry.py（示意）
PROVIDERS = {
    "sector_snapshot":  ["eastmoney", "ths"],   # 板块热力图
    "capital_flow":     ["eastmoney", "ths"],   # A2 资金流
    "daily_kline":      ["baostock", "sina"],
    "valuation":        ["baostock", "baidu"],  # T1/T4 产物
}
```

每个 provider 实现统一接口：`fetch(ctx) -> RawBatch`、`name`、`health()`。
调度器按序尝试，全部失败才写"数据未采集"状态（保留现有不写脏数据原则）。

### 4.2 同花顺备源实现要点

- 行业资金流：`ak.stock_fund_flow_industry(symbol="同花顺行业资金流")`（域名 data.10jqka.com.cn，实测直连可用，需先 import T2 的 http_client 清代理）
- 板块行情备源：`ak.stock_board_industry_name_ths()` / `ak.stock_board_industry_hist_ths()`
- 字段映射层：THS 与 EM 的板块代码体系不同（THS 无标准行业码），**以板块名称为对齐键**，映射表落库，名称对不上的记录丢弃并记日志，不得猜配。
- THS 页面结构变动频繁，解析层失败要能熔断（连续 3 次失败标记 provider unhealthy，跳过 30 分钟）。

## 5. T4：股息率（P2）

按优先级：

1. **首选**：`ak.stock_zh_valuation_baidu(symbol="sh.600000")` 取历史估值（含市值/PE/PB/PS）。注意该接口有频率限制，全市场回填 ≥1s/次 + 断点续传（进度落库，可重跑）。如果其返回含股息率字段则直接用；**若无股息率字段则走方案 2**（接口实际返回字段以开发时实测为准，AI 不要臆造字段名）。
2. **兜底（自算 dv_ttm，纯 baostock，稳定）**：
   - `bs.query_dividend_data(code="sh.600000", year=..., yearType="operate")` 取历次每股分红
   - `dv_ttm = Σ(近 12 个月每股税前分红) / 当日收盘价`，每日滚动计算
   - 分红除权日前后注意价格口径（用不复权价算股息率）
3. 指数级参考可用 `ak.stock_a_gxl_lg`（仅大盘/指数，不用于个股因子）。

验收：样本股 dv_ttm 与乐咕/东财网页展示值偏差 < 0.1pct（抽样 5 只）。

## 6. T5：数据新鲜度标注 + stale-while-error（P1）

1. 采集元数据表（或复用现有状态表）每条记录带：`source, fetched_at, as_of_date, is_stale`。
2. 信号/报告层读取规则：
   - 数据新鲜（as_of_date = 最近交易日）→ 正常出信号
   - 数据 stale（缺 1~N 个交易日）→ **照常出信号，降权并显式标注"数据截至 X 日（N 天前）"**，估值类因子变化慢，stale 容忍度可到 5 个交易日；资金流类容忍 1 天
   - 无任何数据 → 才显示"数据未采集"
3. 前端热力图/因子卡片增加来源与日期角标（如 `东财 · 10-22`）。

验收：人为把某源数据冻结 3 天，A1/A4 仍出信号且标注 stale；资金流 1 天后标 stale。

4. 禁止使用 `stock_a_indicator_lg`（1.19.1 中不存在）。
5. 所有采集入口 import `app/data/http_client.py` 且位于 akshare import 之前。
6. 回填脚本必须幂等、可断点续传、有进度日志；全市场任务放在后台/容器内跑，不阻塞 API。
7. 完成后逐条对照各任务验收标准输出自检报告；未验证的项明确标注"未执行验证"。
